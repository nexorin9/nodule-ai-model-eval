# 判定口径与指标定义

> 这份文档回答两个问题：**每一例凭什么这么判**、**汇总行那几个数是怎么算出来的**。
> 口径的**唯一真源在代码里**，本文是它的可读版本；两边不一致时以代码为准，
> 并用 `python -m pytest tests/test_judge_enum.py tests/test_metrics.py -q` 核对。

---

## 一、五个互斥结论

每一例只落一个判定，五个值**互斥且完备**（2×2 真值表 + 失败出口）：

| 判定 | 含义 | 计入指标分母 |
|------|------|--------------|
| `hit`（命中） | 金标准有结节，模型也报出了对应病灶 | 是 |
| `miss`（漏判） | 金标准有结节，模型没报出（或没盖住其中一处） | 是 |
| `false_positive`（误报） | 金标准无结节，模型报出了 | 是 |
| `true_negative`（真阴性） | 金标准无结节，模型也没报 | 是 |
| `failed`（失败） | 这一例没跑成 —— 调用失败 / 超时 / 检查号不回显 / 响应缺字段 | **否** |

- 真值表在 `src/nodule_eval/metrics/judge.py` 的 `PRESENCE_MATRIX`（键 = 金标准存在性 × 模型是否检出），
  **判定逻辑直接查表**，不另写一份 if-else。
- 完备性与互斥性**不靠注释保证**：`enumerate_verdict_outcomes()` 遍历 12 格输入空间
  （失败 × 存在性有/无/读不出 × 检出）真的跑一遍判定再核对行为，`assert_verdict_completeness()`
  挂在判定口 —— 真值表被改坏当场报 `CONTRACT_INVALID`。
- **失败优先**：判 `failed` 的错误码收窄到「这一例的调用本身没成」
  （`INFERENCE_4XX` / `INFERENCE_5XX` / `INFERENCE_TIMEOUT` / `STUDY_UID_MISMATCH` /
  `FIELD_MAPPING_MISSING`）；**降级码不算失败**（降级例有结论、仍进分母）。

---

## 二、三类不进分母的隔离例

除 `failed` 外，还有两类例也不进 TP / FP / FN / TN。三类**各占汇总行一栏，互不吞并**：

| 隔离类型 | 触发 | 标记 | 进分母 | 汇总栏 |
|----------|------|------|--------|--------|
| 失败 | 调用本身没成 | `failed` | 否 | 失败数 |
| 挂起 | 影像绑定存疑（一对多歧义 / 引用与 RIS 不一致 / 表内检查号重复） | `held` + `needs_review` | 否 | 挂起数 |
| 不可比 | 属性写法认不出、没法核对（`肺门区`、`密度不均`、`左肺中叶`） | `incomparable` | 否 | 不可比数 |

- **失败绝不进分母**：把「没跑成」算成「模型没看见」，敏感度就被算歪了。
- **挂起优先于降级**：一例外挂起又被降级，仍算挂起 —— 影像本身存疑时，用什么口径判都没用。
- **降级（`rule_degraded`）仍进分母**：模型归并未成功、退回规则基线，结论仍成立，
  但单列降级数、优先复核。
- `needs_review` 是「要人看一眼」的**总闸**（挂起 + 降级 + 归并读不出），
  **它本身不决定进不进分母** —— 决定分母的是 `held` / `rule_degraded` 两个标记。
- 口径真源在 `src/nodule_eval/contracts.py` 的 `counts_toward_denominator()` 与 `partition_rows()`，
  判定、指标计算、汇总行、写回体都从这里取，**不各写一份**。

## 三、比对规则

金标准归并出 `(presence, location, size_mm, density)`，模型返回 `candidates`：

1. **存在性**：精确比对 —— 金标准说有、模型报出即存在；
2. **属性三层**：存在性一致且两边都说「有病灶」时，才逐层比**尺寸 / 部位 / 密度**；
3. **尺寸**：容差比较（默认 ±2 mm，`options.size_tolerance_mm` 可配）。**闭区间** ——
   恰好等于阈值算一致（浮点表示误差用 `1e-9` 余量兜住）；
4. **部位**：等价表（`右肺上叶` ↔ `RUL` ↔ `右上叶`，肺段归入所属肺叶）；
5. **密度**：等价表（`磨玻璃` ↔ `GGN`、`实性`、`部分实性`、`钙化`、`空洞`）。

每层四种结论：**一致 / 不一致 / 不可比 / 未比对**。

| 结论 | 什么时候 | 怎么算 |
|------|----------|--------|
| 一致 | 两边写法都能归一到同一标准标签 | 正常命中 |
| 不一致 | 两边都能归一，但标签不同 | 该层判不一致 |
| 不可比 | 有一侧写法不在等价表里（`肺门区`、`左肺中叶`） | 既不当一致（一次命中白送）、也不当不一致（一次命中被算成漏诊），**单独计数并带原因** |
| 未比对 | 金标准没写这一层 | 同样没有可比对象，但原因不同 |

**多候选时按「部位 > 密度 > 尺寸」打分选一个**参与比对，选择依据（含同分个数）落进判定依据字段。

## 四、多标签最严口径

金标准写了 **N 处**病灶，模型就得**盖住 N 处** —— 任一处没盖住即判 `miss`：

- 没盖住的那几处逐条记进 `uncovered_lesions`（部位 / 尺寸 / 密度 + 为什么没盖上），
  漏诊原因文案直接引用；
- **对应关系由部位层定**：部位一致 → 对应；部位不一致 → 不对应（不是同一处病灶）；
  部位认不出来（不可比）→ 密度 / 尺寸**一致可作佐证**，但**不一致不否对应** ——
  **属性对不上不等于「不是那一处」**，把 8mm 量成 9mm 判成漏诊是把测量偏差当成没看见；
- **一个候选只能盖一处病灶**（金标准两处、模型报一处 → 另一处未覆盖 → 判漏诊）；
- 金标准只说「见结节」、没写部位尺寸密度的那一处按**存在性**对应，
  **不因「没写」而算不可比**（没写 ≠ 认不出）。

## 五、四项指标

| 指标 | 算式 | 含义 |
|------|------|------|
| 敏感度（Sensitivity） | `TP / (TP + FN)` | 金标准有结节的例里，模型报出了多少 |
| 特异度（Specificity） | `TN / (TN + FP)` | 金标准没结节的例里，模型没误报多少 |
| 阳性预测值（PPV） | `TP / (TP + FP)` | 模型报出的例里有多少是真的 |
| 阴性预测值（NPV） | `TN / (TN + FN)` | 模型没报的例里有多少是真的 |

- **分母为 0 → 值是 `null` 不是 `0`**，且写明原因：
  「本轮没有金标准阳性的样本（TP+FN=0），分母为 0，敏感度算不出（不是 0）」——
  **「算不出」与「算出来是 0」是两件事**，前者写成 0，评审会上就会拿着一条假结论去否决一款模型。
- **取整用 `Decimal` + `ROUND_HALF_EVEN`**（四舍六入五入成双，保留四位小数），
  不用二进制浮点的 `round()` —— 这一栏要给人拿计算器手算复核，引擎算出来的数必须和计算器一致。
- 原始计数保持整数，`tp + fp + fn + tn` 恒等于进分母例数。
- 汇总行同时带 TP/FP/FN/TN 原始计数 + 失败数 + 规则降级数 + 挂起数 + 不可比数 +
  模型归并数 —— 光给百分比没法核对。

## 六、手算复核

复核的人不必信引擎：

1. **漏诊清单条数 ≡ 漏诊数 FN** —— 清单只收**计入指标分母**的漏诊例，
   数一遍清单就能拿计算器手算敏感度；判了漏诊但因属性不可比没进分母的例单列在
   `summary.json` 的 `missed.not_counted`，**不静默丢行**；
2. **手算复核块**（`summary.json` 的 `manual_check`）把四个算式**连中间值**写出来
   （`TP/(TP+FN) = 120/140 = 0.8571`），并附从逐例明细**反算**出来的原始计数；
3. **对不上当场报错** —— `assert_summary_consistent()` 在落盘前核四件事
   （指标 ↔ 逐例明细、单列栏 ↔ 逐例明细、清单条数 ↔ FN、样本量 ↔ 逐例行条数），
   任何一项对不上抛 `CONTRACT_INVALID` 并**点名差在哪一项** ——
   **不给一份看着正常、其实和明细对不上的结论**。

## 七、口径来源标注

敏感度 / 特异度的定义、结节属性字段（位置 / 大小 / 密度）、±2 mm 尺寸容差、
部位与密度等价表，在院内**资产层无对应条目**，来源为放射科评估表模板、厂商说明书、
伦理批件与招采参数 —— 一律按**经验推断**对待。

**严禁虚构标准号、量限数字或指南名。** 等价表里的每条别名都能在
`src/nodule_eval/goldstd/labels.yaml` 里查到出处与登记状态；认不出来的写法返回 `None`，
**不猜一个近似标签**。
