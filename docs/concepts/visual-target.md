# 视觉目标卡 · 肺结节AI模型评估系统

> 本文件是**结构化视觉目标卡**，不是宣传图。本运行环境无图像生成能力，故不生成、不伪造概念图片；
> 真实运行截图另见 `docs/screenshots/`（由真实评估一轮采集）。

## 画面类型

**表格界面** —— Microsoft Excel（或 WPS 表格）窗口中的评估表，叠加**本机引擎运行日志**（CSV 直跑路径与引擎心跳）。
与本项目锁定的交付形态（表格内插件 + 本机 CLI）一致：**不画 Web 面板、不画大屏驾驶舱**。

## 三个状态

### 1. 起始态

一张空白的评估表纵向铺开：

- **左侧既有列区**（科室维护）：检查号、检查日期、图像引用、金标准描述。金标准是自由文本，单元格内有换行，行高偏宽。
- **右侧大片空白**：产品要追加的六个新列（判定 / 模型结论 / 失败原因 / 调用记录ID / 待复核 / 归并来源）尚未写入。
- **顶部一排三个按钮**：「开始评估」「确认提交」「导出结论表」，此刻是灰的（未选择评估区间时不可点）。
- **底部状态栏**一行灰字：`未选择评估区间`。

### 2. 首个可用瞬间

点「开始评估」后，**表格没有跳走**，仍在原表里：

- 右侧新列一节一节长出来：`判定`（命中 / 漏判 / 误报 / 真阴性 / 失败）、`模型结论`、`失败原因`、`调用记录ID`、`待复核`、`归并来源`。
- 单元格底色按判定分三档：命中浅绿、漏判浅红、失败浅灰黄。
- 顶行汇总区出现敏感度、特异度两个数字（等宽字体，字号比正文大一档），旁边是 TP / FP / FN / TN 原始计数与失败数。
- 底部状态栏变成深色一行：`已评估 186 / 200 例，第 187 例推理超时，已重试 1 次`。

### 3. 成形态

表格底部追加两段：

- **「漏诊明细」段**：按影响排序列出漏判例。点任意一行，右侧弹出该例的**调用记录摘要**（模型标识、版本、入参摘要、返回摘要、耗时）—— 这是调用留痕底账的人话版，供放射科回答「这例凭什么算漏判」。
- **状态栏右侧**出现：`本轮结论已写回评估登记接口（幂等键 8f2c…）`，表示人工确认后的已生效事实层。

## 视觉语言

### 配色

| 用途 | 色值 | 说明 |
|------|------|------|
| 表带底色 | `#F7F8FA` | 灰调底，整表观感不刺眼 |
| 表头 | `#1F3B63` | 深蓝底 + 白字 |
| 命中底色 | `#E3F4E8` | 低饱和浅绿 |
| 漏判底色 | `#FBE3E3` | 低饱和浅红 |
| 失败底色 | `#F5EFE0` | 低饱和浅灰黄 |
| 强调色 | `#0F6F4B` | **仅一处** —— 「确认提交」按钮，其余控件一律灰 |

三档判定底色均为低饱和，可直接黑白打印后逐行核对。

### 字体族

- 正文与数字：**等宽**（`Consolas` 等，中文回落到等宽中文字体）—— 逐例判定与指标要能上下对齐比较；数字列右对齐并用 `tabular-nums` 对齐。
- 按钮与表头：系统无衬线（`-apple-system` / `PingFang SC` / `Microsoft YaHei`）。

### 信息层级

1. 右上汇总区的两个指标数字最显眼（字号最大、加粗）；
2. 逐例判定列靠底色扫读；
3. 漏诊明细段是「下一步该看哪儿」的落点；
4. 调用记录只在点开时出现，不占常态视野。

### 留白密度

密而不挤 —— 列宽固定、每列只放一个信息维度；表头与首行冻结；行高偏宽以容纳金标准的多行文本。

## 必须可达的约束

只画当前依赖真能做出来的东西：

- 底色分档：xlsm 条件格式与单元格样式即可，无需任何图形库。
- 弹出调用记录摘要：Excel 内嵌区域或宏写出的右侧区域均可；**不画**浮层气泡动画。
- 状态栏心跳：本机引擎写状态文件，宏轮询读取后写入状态栏单元格。
- **不画** WebGL / 3D / 大屏 / 动画流程图 —— 本轮形态是表格内插件，画不出也用不上。
