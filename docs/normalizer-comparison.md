# 归并对照实验：规则基线 vs 模型归并

> **这份文档回答一个问题**：模型归并这一层到底值不值得加？
> 答案不靠嘴说，靠**同一批人工标注的写法**上逐字段对照出来的数字。

- **裁判集**：`src/nodule_eval/goldstd/benchmark.yaml` —— 66 条放射科胸片金标准自由文本写法，
  每条带**人工标注**的标准标签（部位 / 尺寸 / 密度 / 存在性 / 病灶处数）。
  六类场景：基础阳性、基础阴性、否定作用域、多病灶、跨行拼接、量纲混写、别名与书写变体、术语外写法。
- **对照脚本**：`scripts/compare_normalizers.py`
- **产物**：`reports/normalizer-compare/`（`compare-normalizers.csv` 逐例明细 /
  `compare-summary.json` 汇总 / `compare-run-meta.json` 运行元信息）
- **本轮跑法**：`--model-mode double`（模型侧 = 本地协议替身，**不是真实大模型**，见文末声明）

---

## 一、结论先行

| 结论 | 依据 |
|------|------|
| **模型这一层值得加 —— 但目前只在「存在性」一层兑现。** | 规则基线在 66 条里有 **2 例整句读不出存在性**（形态描述类写法：`类圆形高密度影` / `条片状高密度影`）。模型侧把这两例救回来后，存在性召回从 **96.2% → 100%**。 |
| **属性层当前拿不到模型增益。** | 回指校验要求模型给的标签**必须能在原文里找到**，而模型与规则认的是**同一张等价表**。模型凭语义补出的别名（`钙化灶` / `高密度影` / `密度不均` / `右肺底`）会被判解析失败并降级 —— **要兑现语义能力，先扩等价表（数据），再谈换更强的模型。** |
| **语义归并当前只落一条病灶标签** —— 多病灶口径上模型侧比规则侧差。 | 7 例多病灶写法上，模型侧病灶处数恒为 1，规则侧能给到 2。这是**契约缺口**（`goldstd/merge.py` 的 `_build_lesions` 只落一条），要靠任务 27 / 28 的最严比对补齐，**不是模型能力问题**。 |
| **规则基线仍不可替代。** | 模型端点不可达时它能独立跑完整条主干；它是**回指校验与标签复核的基准**（没有它，模型给的标签无从复核）；模型输出不合契约时降级到它，而不是把这一例判失败。 |

| 部位 | 93.9% | **95.5%** | +1.5% | 92.3% | 94.2% | 0.0% | 0.0% |

| 密度 | 90.9% | 90.9% | +0.0% | 88.2% | 88.2% | 6.2% | 6.2% |

> **误召率** = 原文没写这一项、归并器却给了一个值的比例（拉低特异度）。
> **召回** = 原文确实写了、归并器读对的比例（漏召直接扣在这里）。
> 存在性的误召率 14.3% 指的是 **2 例阴性被判成阳性** —— 方向与漏召相反，两类错必须分开看。

## 三、规则基线在哪些地方失效（逐例，可复核）

对照表里每一行都能在 `reports/normalizer-compare/compare-normalizers.csv` 里按 `case_id` 查到。

### 1. 否定作用域：并列的第二个病灶词没被否定管住（2 例 · 拉低特异度）

| 用例 | 原文 | 规则读成 | 标注 |
|------|------|---------|------|
| bm-015 | 双肺未见结节影及钙化灶。 | 阳性 + 密度=钙化 | 阴性、无密度 |
| bm-023 | 双肺未见结节影及磨玻璃影。 | 阳性 + 密度=磨玻璃 | 阴性、无密度 |

否定词「未见」只管住了并列描述里的**第一个**病灶词，第二个（「钙化灶」「磨玻璃影」）被当成了病灶。
**这类错的方向是「阴性判成阳性」** —— 直接拉低特异度，也会在报告里变成一份「模型报了假阳性」的假账。

### 2. 术语外写法：形态描述读不出存在性（2 例 · 连带三项漏召）

| 用例 | 原文 | 规则读成 | 标注 |
|------|------|---------|------|
| bm-061 | 两肺纹理增粗，右上肺见类圆形高密度影。 | 存在性读不出、部位空、密度空、病灶 0 处 | 阳性、右肺上叶、实性、1 处 |
| bm-062 | 左肺门区见条片状高密度影。 | 同上 | 阳性、左肺、实性、1 处 |

病灶词表收的是「结节 / 磨玻璃 / 实性 / 病灶 / 肿块 / 阴影 / 斑片 / 粟粒 / 钙化 / 空洞 / 囊性」，
**没收**「类圆形高密度影」「条片状高密度影」这类形态描述。整句读不出存在性，
于是部位、密度、病灶处数**跟着一起丢** —— 一个词表的缺口，赔上四个字段。

### 3. 密度等价表的缺口（2 例）

| 用例 | 原文 | 规则读成 | 标注 |
|------|------|---------|------|
| bm-064 | 右下肺见一高密度结节影。 | 密度空（「高密度影」不在密度等价表里） | 实性 |
| bm-066 | 右下肺见一结节影，密度不均。 | 密度空（「密度不均」不在密度等价表里） | 部分实性 |

（「钙化灶」这类写法**认得出来** —— 别名 `钙化` 是它的子串，扫描时能命中；
真正缺的是 `高密度影` / `密度不均` 这类**整体新词**。）

**这两例是最便宜的收益**：把 `高密度影` / `密度不均` 补进
`src/nodule_eval/goldstd/labels.yaml` 的密度别名，规则与模型**同时**受益 —— 不用换模型。

### 4. 尺寸：三种写法读不出（3 例）

| 用例 | 原文 | 规则读成 | 标注 |
|------|------|---------|------|
| bm-042 | 右下肺见一实性结节影。⏎最大径约 1.0cm。 | 尺寸空（尺寸写在下一句） | 10.0 |
| bm-049 | 右下肺见一结节影，直径约一公分。 | 尺寸空（中文数字） | 10.0 |
| bm-050 | 右下肺见一结节影，大小约 8×6mm。 | 尺寸空（两径写法） | 8.0 |

**bm-042 是模型侧修好的那一例** —— 尺寸写在下一句，规则基线按「段内借用」的纪律不认，
模型侧能读出来。**bm-049 / bm-050 两边都读不出**：中文数字与两径写法的正则要扩，
扩的是 `goldstd/rules.py` 的尺寸正则 —— **扩完两边同时受益**，模型仍然拿不到增量。

### 5. 部位别名缺口（2 例）

| 用例 | 原文 | 规则读成 | 标注 |
|------|------|---------|------|
| bm-056 | 右肺底见小结节影。 | 右肺 | 右肺下叶 |
| bm-035 | 右肺中叶及右下肺各见一结节影。 | 右肺下叶、病灶 1 处 | 右肺中叶、病灶 2 处 |

bm-056 是别名缺口（「右肺底」不在部位等价表里，表里只有「右肺尖」）；
bm-035 是「及」连接的两个肺叶没被拆成两处，首处投影也因此取错。

## 四、模型侧的增益与代价（逐字段核对）

模型侧相对规则基线：**修好 6 个字段、弄坏 7 个字段**（逐条见 CSV）。

| 方向 | 用例 | 字段 | 说明 |
|------|------|------|------|
| ✅ 修好 | bm-061 / bm-062 | 存在性 | 形态描述当病灶词，模型侧能给出结论 |
| ✅ 修好 | bm-062 | 部位 | 病灶成立后在**证据句**里把部位捞回来 |
| ✅ 修好 | bm-061 / bm-062 | 病灶处数 | 从 0 处变 1 处 |
| ✅ 修好 | bm-042 | 尺寸 | 尺寸写在下一句，模型侧能跨句读出 |
| ❌ 弄坏 | bm-031 ~ bm-038（7 例） | 病灶处数 | 语义归并当前只落**一条**病灶标签 |

**弄坏的这 7 例不是模型读不出来，是契约没跟上**：
`goldstd/merge.py` 的 `_build_lesions` 只把顶层四元组落成一条 `LesionLabels`，
多病灶口径要靠任务 27 / 28 的**最严比对**逐处对。
**换更强的模型解决不了这一条** —— 得改契约。

## 五、给决策的三条建议

1. **先补数据，再谈模型。** 密度别名（`高密度影` / `密度不均`）、
   部位别名（`右肺底`）、尺寸正则（中文数字 / 两径写法）—— 三处都在
   `src/nodule_eval/goldstd/labels.yaml` 与 `rules.py` 里，改完规则与模型**同时**受益。
2. **模型这一层的价值集中在「规则读不出存在性」的那一类写法。**
   胸片报告里的形态描述远比「结节影」多，这一层不补上，敏感度就没有底。
   但**要把它落成收益，先把模型能读出的别名补进等价表** ——
   否则模型凭语义补出的标签会被回指校验挡回来，白跑一趟。
3. **规则基线不要下线。** 它是降级落点、是回指校验的基准、也是模型不可达时
   唯一能跑完整条主干的路径（任务 24 已验：3 例全降级仍出结论、run 状态仍停在 `evaluated`）。

## 六、口径声明（**读数字前先看这一段**）

- **本轮模型侧不是真实大模型。** `--model-mode double` 那一侧的应答逻辑是
  `tests/semantic_reader.py` 里的一段**确定性 Python 代码**（比规则基线多认一些形态描述，
  并在证据句里回捞属性），**不是**大模型。它给出的数字代表
  **「一个比规则基线宽一点的确定性读法，在同一套回指校验与标签复核约束下能拿到什么」**，
  **不代表真实模型的能力**。院内模型端点可用后，用同一条命令重跑：

  ```bash
  OPENAI_BASE_URL=... OPENAI_API_KEY=... OPENAI_MODEL=... \
    python scripts/compare_normalizers.py --model-mode gateway
  ```

  拿到的才是可对外汇报的数字；`--record <log.jsonl>` 可把本轮返回录下来，
  之后用 `--model-mode replay --model-log <log.jsonl>` **逐字节复现**（不发任何请求）。

- **裁判集是分层构建的，不是随机抽样。** 每一类都是「这一类写法」，
  所以准确率**不代表真实世界的写法分布**，只用于**层与层之间的对照**。
  要估「真实报告里有多少比例会落到某一类」，得另做一次分层抽样。

- **标注是单点标注。** 66 条由本轮按放射科报告写法逐条标注，
  **未做双人标注与一致性验证**（`spec.md` 已写明这一限制）。

- **数字可复现。** 文件头记下：裁判集版本号与内容哈希、随机源（seed）、
  模型参数（温度 0）、以及提示词 / 等价表 / 规则 / 契约 / 语义归并五个源文件的哈希。
  同一条命令跑两遍，`compare-normalizers.csv` 与 `compare-summary.json` **逐字节一致**
  （`tests/test_compare_normalizers.py` 有断言）。

## 七、怎么自己跑一遍

```bash
# 离线核验（模型侧 = 本地协议替身，确定性、可复现）
python scripts/compare_normalizers.py --model-mode double

# 打院内真实模型端点（凭据只从环境变量读，缺一项就指名报错）
OPENAI_BASE_URL=... OPENAI_API_KEY=... OPENAI_MODEL=... \
  python scripts/compare_normalizers.py --model-mode gateway

# 复跑同一批数据的一部分（抽样由 seed 决定，可复现）
python scripts/compare_normalizers.py --model-mode double --sample 12 --seed 20260907
```

逐例明细看 `compare-normalizers.csv`（列：`case_id` / `category` / `normalizer` /
`field` / `expected` / `actual` / `status` / `error_type` / `error_label` / `text`）。
